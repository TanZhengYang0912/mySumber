# Groq AI Anomaly Analysis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a real, user-triggered Groq analysis flow to Admin AI Anomaly Review and persist the validated result on the same Supabase `alerts` row.

**Architecture:** Keep the deterministic Alert detection and Oversight status/severity as the system source of truth. Add a small immutable response model and an injected Groq HTTP service; `AppState` coordinates one analysis request per alert and persists validated fields through `LeakageRepository`. The Review detail page owns the user interaction and renders saved or newly generated analysis without calling the old customer-review summary flow.

**Tech Stack:** Flutter/Dart, Provider, `http`, Groq OpenAI-compatible Chat Completions API, Supabase PostgreSQL/Data API, `flutter_test`.

## Global Constraints

- Call Groq only after Admin taps `Generate AI Analysis` for one selected anomaly.
- Use Groq model `llama-3.1-8b-instant` and endpoint `https://api.groq.com/openai/v1/chat/completions`.
- Use JSON object mode (`response_format: {"type":"json_object"}`) and validate the response locally before persistence.
- Save validated `summary`, `possible_cause`, `recommendation`, `severity_assessment`, `confidence`, and `ai_generated_at` to the same `alerts` row.
- Never change `Alert.status` or the system `Alert.severity` from AI output.
- Do not send customer email, star rating, review comment, Worker photo, or repair result to Groq.
- Do not call Groq while the Review list loads.
- Do not call the old customer-review `generateAiSummary()` method from Admin Review.
- Use the existing `lib/config.dart` Groq key; never commit that file or any service-role key.
- Preserve the existing Inventory, Oversight, customer, and Worker flows except for the focused Review/API changes.
- The `alerts`, `readings`, and `reports` base tables must exist before applying the AI column migration; the repository already contains the required base-schema SQL instructions for the empty Supabase project.

}
